# 모바일 현지화 원리

## 1. 언어는 사용자 상태다

번역 함수가 전역 문자열을 바꾸는 것만으로는 충분하지 않다. locale 변경은 구독 중인
모든 화면을 다시 렌더링해야 하며, 앱 재시작 뒤에도 동일해야 한다. React context에 연결된
단일 i18n 인스턴스와 영속 locale만 사용한다.

## 2. 한국어가 의미 정본이다

이룸은 한국어 우선 제품이다. 기능명, 정직성 고지, 의료 비대체 문구의 의미 정본은
`apps/web/messages/ko.json`이다. 모바일 런타임에는 화면에 필요한 부분만 투영할 수 있지만,
동일 키의 한국어 의미를 고쳐 쓰지 않는다. 테스트가 정본과의 불일치를 막는다.

## 3. 폴백은 정직해야 한다

- 미지원 기기 언어는 한국어로 폴백한다.
- 번역이 없는 키는 다른 의미의 임의 문장으로 대체하지 않는다.
- 영어·일본어·중국어 지원을 선언하려면 해당 화면의 모든 가시 문자열과 접근성 문구가
  번역되어 있어야 한다.

## 4. 화면이 마이그레이션 단위다

한 화면을 키화하고, 그 화면의 한국어 회귀 테스트와 다른 locale 렌더 테스트를 통과시킨
뒤 다음 화면으로 이동한다. 파일 전역 정규식 치환으로 여러 화면을 한꺼번에 바꾸지 않는다.
이는 문맥 없는 번역과 테스트 사각지대를 줄인다.

## 5. 문화화는 직역보다 우선한다

영어는 기능·안전 의미를 짧고 직접적으로 전달한다. 일본어 체형 분석은 현지에 통용되는
`骨格診断` 문화를 활용하되 의료 진단처럼 과장하지 않는다. 중국어는 간체(`zh-Hans`)를
사용한다. 법적·비의료 고지는 원문의 방어선을 줄이지 않는다.

## 6. 표시 포맷은 문자열 조립과 분리한다

날짜·숫자·통화는 Hermes의 표준 `Intl` API로 locale에 맞게 포맷한다. 조사나 어순을
문자열 덧붙이기로 만들지 않고, 완전한 문장과 named interpolation을 번역 단위로 둔다.
