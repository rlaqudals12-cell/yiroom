# ADR-122: 모바일 i18n 런타임과 점진 전환

## 상태

`accepted`

## 날짜

2026-09-05

## 0. 궁극의 형태 (P1)

### 이상적 최종 상태

“지원한다고 선언한 모든 언어에서 설치부터 재방문까지 같은 기능·안전 의미를 제공한다.”

- 웹과 모바일이 하나의 한국어 의미 정본을 따른다.
- locale 변경이 앱 전체에 즉시 반영되고 재시작 뒤에도 유지된다.
- 누락 번역·placeholder 불일치·한국어 하드코딩 회귀가 테스트에서 차단된다.
- 언어별 어법은 현지 문화에 맞지만 정직성·비의료 계약은 약화되지 않는다.

### 물리적 한계

| 항목          | 한계                                                                    |
| ------------- | ----------------------------------------------------------------------- |
| 전체 화면 수  | 모바일 하드코딩 문자열을 한 번에 바꾸면 문맥·회귀 검증이 불가능하다.    |
| 카탈로그 크기 | 웹 4개 전체 JSON을 모바일 번들에 그대로 싣지 않는다.                    |
| 동적 콘텐츠   | AI 결과와 제휴 제품 원문은 정적 UI 카탈로그만으로 완전 번역되지 않는다. |
| 검수 순서     | `en` 검수 후 `ja`, `zh-Hans` 순으로 확장한다.                           |

### 100점 기준

- 지원 locale의 화면 가시 문자열·접근성 문자열 키화 100%
- 웹 한국어 정본과 모바일 투영본 의미 불일치 0
- locale 변경 구독 누락 0
- 카탈로그 키·interpolation 불일치 0
- 미지원 locale에서 한국어 폴백 성공 100%

### 현재 목표: 45%

- `ko/en` 카탈로그 기반을 만들고 로그인 화면부터 화면 단위로 전환한다.
- 영어 카탈로그는 검수하되, 미전환 화면이 남은 동안 공개 앱 locale은 `ko`로 유지한다.
- 웹 잔여 하드코딩과 AI 동적 콘텐츠 번역은 포함하지 않는다.

### 의도적 제외

| 제외 항목                  | 이유                   | 재검토 시점                    |
| -------------------------- | ---------------------- | ------------------------------ |
| 웹 잔여 하드코딩 전수 치환 | 별도 배치로 명시됨     | 모바일 핵심 여정 전환 후       |
| `en` 공개 활성화           | 부분 영문 앱 노출 방지 | 첫 사용자 핵심 여정 전환·QA 후 |
| `ja/zh-Hans` 앱 UI 활성화  | 영어 검수 선행 계약    | 영어 핵심 여정 검수 완료 후    |
| 번역 SaaS·OTA 카탈로그     | 현재 규모에 과함       | 상시 번역 운영 인력 확보 시    |
| RTL                        | 출시 시장 범위 밖      | RTL 시장 진입 결정 시          |

## 1. 맥락

ADR-018은 i18n을 단계적으로 도입한다고 정했지만 모바일 라이브러리와 반응성 계약은
고정하지 않았다. 저장소에는 손제작 `lib/i18n`이 있으나 화면 소비처가 없고, 전역 locale과
훅별 state가 분리되어 언어 변경을 앱 전체에 전파하지 못한다. Play 한국어 선공개 이후
영어·일본어·중국어 확장을 위해, 화면별로 검증 가능한 런타임 기반이 필요하다.

## 2. 결정

1. 모바일 번역 런타임은 `i18next` + `react-i18next`로 고정한다.
2. 기기 locale은 이미 설치된 `expo-localization`의 첫 선호 언어를 사용한다.
3. 사용자 선택은 기존 AsyncStorage 키 `@yiroom/locale`에 저장한다. 저장소 조회가 1초 안에
   끝나지 않으면 기기 locale(현재 공개 범위에서는 `ko`)로 확정해 앱 진입을 막지 않는다.
4. 카탈로그는 `ko/en`부터 구축하되 공개 locale은 `ko`다. 기본 및 누락 폴백도 `ko`다.
5. 기존 import 경로 `@/lib/i18n`과 `t`, `useTranslation`, `getLocale`, `setLocale`,
   `initI18n` 표면은 유지해 점진 전환 중 호출부를 흔들지 않는다.
6. 한국어 의미 정본은 `apps/web/messages/ko.json`이다. 모바일은 전 화면 카탈로그를
   번들링하지 않고 화면별 키만 투영하며, 정본 일치 테스트를 둔다.
7. 마이그레이션은 화면 단위다. 화면의 로직·디자인은 바꾸지 않고 가시 문자열,
   placeholder, Alert, 접근성 문구만 키로 이동한다.
8. `en` 공개 활성화는 첫 사용자 핵심 여정의 화면·오류·접근성 문구가 모두 키화되고
   영어 QA를 통과한 뒤 별도 플래그 변경으로 수행한다.

## 3. 대안

| 대안                        | 장점                                  | 단점                                             | 판정 |
| --------------------------- | ------------------------------------- | ------------------------------------------------ | ---- |
| 현행 손제작 모듈 보강       | 의존성 추가 없음                      | React 전역 갱신·plural·초기화 문제를 직접 재구현 | 기각 |
| `i18n-js` + 자체 provider   | Expo 예제와 가까움                    | 핵심 반응성 계층을 새로 발명해야 함              | 기각 |
| `react-intl`                | ICU 포맷이 강함                       | 현 단계에 불필요한 RN polyfill/ESM 설정 표면     | 기각 |
| `i18next` + `react-i18next` | RN 지원, 반응성, 폴백·보간, 점진 도입 | 의존성 2개                                       | 채택 |

## 4. 결과

### 긍정적 결과

- 한 화면에서 바꾼 locale이 모든 구독 화면에 전파된다.
- 기존 호출 경로를 유지해 화면별 안전 전환이 가능하다.
- 모바일 번들에 웹 전체 카탈로그를 싣지 않는다.
- 영어 이후 일본어·간체 중국어를 같은 런타임으로 확장할 수 있다.

### 부정적 결과

- 웹 정본과 모바일 투영본 사이에 복사 단계가 남는다.
- 마이그레이션 중 키화 화면과 한국어 하드코딩 화면이 공존한다.

### 리스크와 완화

- 정본 drift: 정본 일치 테스트로 차단한다.
- 첫 프레임 언어 튐: 루트에서 저장 locale 초기화를 마친 뒤 화면을 연다.
- 저장소 무한 대기: 조회를 1초로 제한하고, 시간 초과 뒤 늦은 응답은 초기 언어를 바꾸지 않는다.
- 부분 영문 노출: 영어 QA 전까지 기기 감지·설정에서 `en`을 공개하지 않는다.

## 5. 구현 가이드

```ts
const resources = {
  ko: { translation: ko },
  en: { translation: en },
} as const;

i18n.use(initReactI18next).init({
  resources,
  lng: 'ko',
  fallbackLng: 'ko',
  supportedLngs: ['ko', 'en'],
  interpolation: { escapeValue: false },
  initAsync: false,
});
```

- `initI18n()`은 저장 locale을 최대 1초 기다린 뒤 검증한다. 시간 초과 또는 공개 허용 목록
  밖이면 기기 locale을 거쳐 `ko`를 유지한다.
- `setLocale()`은 `changeLanguage()` 성공 후 같은 locale을 저장한다.
- 화면 테스트는 한국어 기본 렌더와 영어 카탈로그 렌더를 각각 단언한다.
- 카탈로그 테스트는 key parity, placeholder parity, 웹 한국어 정본 일치를 단언한다.
