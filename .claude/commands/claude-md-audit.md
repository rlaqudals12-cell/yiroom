# /claude-md-audit 명령어

**목표**: CLAUDE.md를 완전·명확·자립적으로 만들어, 더 저렴한 모델(Sonnet 등)이나 새 세션의 모델이 **이 파일만 따라도** 기준 모델(Opus 4.8)에 근접한 품질을 내도록 한다.

**역할**: 너는 이 프로젝트의 시니어 엔지니어링 리드다. 순서대로 진행한다.

## 대상

$ARGUMENTS (미지정 시 루트 `CLAUDE.md` + 관련 앱별 `apps/*/CLAUDE.md`)

## 1. 점검 (Audit)

현재 CLAUDE.md 전체와 **실제 프로젝트**를 충분히 읽어 파일이 현실과 맞는지 판단한다:

- 폴더 구조, 핵심 파일, 최근 커밋(`git log --oneline -20`), 실제 작업 방식
- `.claude/rules/` 로딩 방식 확인 — `paths:` 프론트매터 **없는** 규칙은 매 세션 무조건 로딩되어 주의력을 희석한다. 비대한 always-on 지침은 Anthropic 문서상 **준수도를 떨어뜨린다.**

다음을 **전부 목록으로** 뽑는다:

- 모호한 지시 / 서로 모순되는 지시 / 낡아서 현실과 다른 것 / 빠진 것 / 모델이 "머릿속에서 채워 넣어야만" 돌아가는 암묵적 관습

## 2. 업그레이드 (Upgrade)

CLAUDE.md를 완전하고 모호하지 않게, 그 자체로 충분하게 다시 쓴다:

- 프로젝트 목적·스택·지켜야 할 기준을 명확하고 **검증 가능한** 언어로
- 암묵적인 것을 명시화 — 새 모델이 틀리기 쉬운 관습 + 사용자 선호를 잡아낸다
- 모순과 죽은 지시는 지운다
- **"완료의 정의(Definition of Done)"** 와 **종료 전 체크리스트**(이 저장소 Verify-Loop: `typecheck + lint + test`)를 짧게 추가한다
- 사용자 말투, 기존 규칙, **"하드 룰"로 표시된 건 그대로 살린다**
- 사용자가 말한 적 없는 선호는 지어내지 말고, 애매하면 사용자에게 물어본다
- 200줄 초과 시: 상세는 `.claude/rules/`의 **경로 스코프 규칙**(`paths:` 프론트매터)으로 분리해 always-on 지침을 최소화한다

## 3. 작업 내역

- 바꾼 부분마다 전후 diff와 한 줄 이유
- 미해결 질문 정리

## 출력 형식

```markdown
## CLAUDE.md 점검 결과

### 발견 사항 (모호/모순/낡음/누락/암묵)

1. [항목] — [문제] — [근거 파일/커밋]

### 변경 내역 (diff + 이유)

- [before → after] : [한 줄 이유]

### 미해결 질문

1. [사용자 확인 필요 항목]
```

## 하드 룰

- 최종 결과물은 **개선된 CLAUDE.md와 변경 요약만**. 다른 파일은 건드리지 않는다.
- 선호를 지어내지 않는다. 애매하면 반드시 묻는다.
